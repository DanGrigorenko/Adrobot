# Adrobot

Локальный интерфейс кампаний Keitaro. Срезы #9–12: поиск кампаний, просмотр потоков и привязок, сохраняемые версионируемые черновики, изменение долей и Pin/Unpin, **Creator с резюме, подтверждением создания и восстановлением операции**. Creator записывает в Keitaro только после явного подтверждения: выключенная кампания → два проверенных потока → включение с проверкой. Cancel и Push ещё не реализованы; действия Editor не публикуют изменения.

## Запуск

Нужны Docker Engine и Docker Compose v2.24.4+ (или v5). Node.js и Python на машине проверяющего не требуются.

```sh
cp .env.example .env
# В локальном .env задайте адрес вашего Keitaro и серверный API-ключ.
docker compose up --build -d
docker compose ps
```

Откройте **http://127.0.0.1:8000**. FastAPI раздаёт React-сборку и API с одного адреса. Frontend собирается в Docker. Проверка готовности: `curl --fail http://127.0.0.1:8000/api/health`.

- `KEITARO_BASE_URL` — корневой HTTP(S) адрес Keitaro, **без** `/admin_api/v1`, query, fragment, имени пользователя и пароля. Для удалённого Keitaro используйте HTTPS. Ключ передаётся только сервером в заголовке `Api-Key`; в UI, bundle и журналы он не попадает.
- `CREATOR_DOMAIN_ID`, `CREATOR_GROUP_ID`, `CREATOR_TRAFFIC_SOURCE_ID` — положительные ID существующих домена, группы кампаний и источника трафика. Пустые/недоступные настройки блокируют резюме Creator, но не просмотр Editor. Проверяются чтением Keitaro при открытии Creator и повторно при проверке резюме. `CREATOR_NAME_PREFIX` — необязательный префикс тестового профиля вместе с разделителем (пример `test_example_`); итоговое имя рассчитывает сервер, уже введённый префикс не дублируется.
- `KEITARO_API_KEY` — ключ с правами чтения кампаний, потоков, каталога офферов, доменов, групп кампаний и источников; для Creator также нужны создание кампаний/потоков и включение кампаний. `.env` не коммитится и исключён из Docker build context. Не запускайте обычные тесты с настоящими секретами.
- `APP_ORIGIN` — точный адрес браузера, по умолчанию `http://127.0.0.1:8000`. Изменяющие HTTP-запросы требуют совпадающий `Origin`, заголовок `X-Adrobot-Request: 1` и отсутствие `Sec-Fetch-Site: cross-site`; действия над черновиком и POST `/api/creator/preview` также требуют эту проверку, хотя не изменяет ни Keitaro, ни локальные данные. GET открытия потока идемпотентно сохраняет только начальный локальный снимок. Проверяется Host; CORS не открыт.
- SQLite находится в именованном томе `sqlite-data`, `/data/adrobot.sqlite`. Один контейнер приложения, один процесс backend. Не масштабируйте приложение и не открывайте порт в интернет. Для удалённого доступа используйте SSH-туннель.
- Alembic выполняет миграции в ASGI startup **до приёма запросов**. Ошибка останавливает запуск, а не создаёт пустую БД в обход миграций. Healthcheck не проверяет доступность Keitaro: сетевые ошибки показаны отдельно в UI.

`docker compose down` сохраняет данные. `docker compose down --volumes` **удаляет** их.

## Что проверять в интерфейсе

1. Найдите кампанию по названию без учёта регистра или точному ID. Выберите её; сверху находятся имя, ID, время успешного чтения, ссылка в Keitaro и обновление потоков. Выбор сохраняется в URL, обновление страницы снова открывает кампанию.
2. Откройте Regular/Default со схемой `landings`. Впервые создаются база и черновик версии 1; все привязки незакреплены. Название и ID оффера, доля, статус и Pin показаны отдельно. Прямой редирект и неизвестные типы — только просмотр, без создания черновика.
3. Убедитесь, что исходные 70/30 остаются 70/30. Активная запись 0% не становится disabled. Disabled сохраняет долю, но не участвует в сумме активных. 20/20, дробные и выходящие за диапазон значения показаны без исправления с причиной запрета будущей публикации.
4. Измените привязки выделенного тестового потока непосредственно в Keitaro **только с разрешения владельца**, затем обновите потоки. Старые база и черновик не заменяются; появляется конфликт и раскрываемое сравнение с текущим состоянием. Простая перестановка привязок не является конфликтом. Этот срез не разрешает конфликт и ничего не публикует.
5. Проверьте поиск без результата, кампанию без потоков, сетевую ошибку и повтор. При неудачном обновлении уже прочитанные данные остаются с предупреждением об устаревании. Поля и кнопки доступны с клавиатуры; узкие таблицы прокручиваются горизонтально.
6. Для активной привязки задайте целое 0–100 и нажмите «Применить» (или Enter). Доля закрепляется, остаток сервер делит между незакреплёнными; остаточные единицы — по возрастанию ID. Например, 34/33/33 → задать первому 50 → 50 Pin/25/25 → Unpin → 34/33/33. Pin без ввода доли ничего не перераспределяет; disabled не редактируется.
7. При закреплённых 60% попробуйте другой активной привязке задать 50%: отказ сохраняет весь черновик и Pin. Дробный, отрицательный и превышающий 100 ввод не принимается. Откройте две вкладки: действие с прежней версией отклоняется с предложением перечитать потоки. Другие потоки независимы.
8. Перезапустите/пересоздайте контейнер без удаления тома: база, черновик, версия и Pin остаются прежними. Обновление потоков не отменяет изменения и не выравнивает исходные 70/30.

Контракт действия: `POST /api/campaigns/{campaign_id}/streams/{stream_id}/actions`, JSON `{"version":1,"action":"share","offer_id":9,"share":50}`. Другие действия: `pin`, `unpin` без `share`. Ответ — сохранённые `version`, `base`, `bindings`; 409 означает устаревшую версию или неподдерживаемый поток, 422 — недопустимое действие. Проверка версии и сохранение защищены одной SQLite-транзакцией. Сетевое чтение поддерживаемости выполняется до транзакции; записи в Keitaro нет.

### Creator: ручная приёмка #10–11

1. Нажмите «Новая кампания (Creator)». Проверьте показанные домен, группу и источник с ID; ошибка настройки имеет отдельный повтор проверки и блокирует резюме.
2. Введите `campaign1`, затем `test_example_campaign1` при тестовом префиксе `test_example_`: до отправки видно одинаковое итоговое имя с одним префиксом. Для своего профиля используйте свой префикс из окружения.
3. Введите `DE`, затем `DE, FR, DE`. Найдите оффер по названию или точному ID, выберите результат; выбранный ID виден независимо от дальнейшего поиска. Проверьте пустой поиск.
4. Нажмите «Проверить и показать резюме». Проверьте имя, настройки кампании (disabled, position), Regular: выбранные страны → `https://google.com`; Default: остальные → выбранный оффер 100%. GEO в резюме без повторов. Отдельная кнопка подтверждает создание и включение; само резюме ничего не записывает.
5. Измените любое выбранное значение: старое резюме исчезает. Неверный GEO (`XX`), недоступный оффер или настройка запрещают резюме с русским объяснением; Keitaro не изменяется. После ошибки данные формы остаются для исправления.
6. На локальном fake (команды ниже) подтвердите создание. Появляется сохранённая операция, затем подтверждённое активное состояние и ссылки в Editor/Keitaro. Пройдите форму клавиатурой, в том числе Enter для поиска оффера; проверьте узкий экран. На живом Keitaro выполнять создание можно только с отдельным разрешением владельца.
7. Для потери ответа на fake перед созданием выполните `curl --fail --json '{"mode":"lose-regular"}' http://127.0.0.1:18081/control`. После подтверждения показан неизвестный исход на этапе Regular. Пересоздайте только контейнер приложения без удаления тома; в Creator операция остаётся. Нажмите «Проверить и продолжить эту операцию»: Regular сопоставляется чтением, создаётся только отсутствующий Default, затем проверка и включение. Повтор после успеха не записывает ничего.

`POST /api/creator/operations`: JSON `{"operation_id":"UUID","name":"campaign1","geos":["DE"],"offer_id":9}` сохраняет идентичность, вход и выделенный alias **без сетевого запроса**. Повтор UUID возвращает ту же операцию, другой вход с тем же UUID — 409. `GET /api/creator/operations` и `GET /api/creator/operations/{id}` доступны после перезапуска. `POST /api/creator/operations/{id}/continue` явно проверяет и продолжает; все POST защищены CSRF. Одновременное продолжение одной операции — 409, ожидание сети не удерживает SQLite-транзакцию. Поддерживается один процесс backend.

Намерение каждого шага фиксируется до записи. При неизвестном результате выполняются только чтение и сопоставление этого шага; отсутствие объекта или прежнее disabled не доказывает завершение предыдущего запроса и не разрешает повтор. Коллизия alias, неоднозначность и несовпадение конфигурации останавливают запись с причиной. Автоматического повтора при запуске нет. Alias — корреляция, **не обещание серверной идемпотентности**; внешнюю гонку Keitaro исключить нельзя. При неразрешимой неопределённости нужна отдельная ручная проверка владельцем, а не новая операция для того же намерения.

### Резервная копия остановленной БД

Копируйте только после остановки приложения, не во время записи:

```sh
docker compose stop app
mkdir -p backups
docker compose cp app:/data/adrobot.sqlite backups/adrobot.sqlite
docker compose start app
```

Резервная копия содержит локальные снимки кампаний/привязок; храните её как приватные данные. Не добавляйте её в Git.

## Тесты без настоящего Keitaro

Для API-тестов нужен Python 3.13+:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

API-тесты используют настоящие FastAPI, сценарии Creator/чтения/редактирования Editor, миграции и файловую SQLite. Creator дополнительно проверяет один/несколько GEO, нормализацию/дубли и неверные коды ISO, имя с/без префикса, поиск оффера, отсутствующие/недоступные настройки, недоступный оффер и безопасные ошибки чтения. Примеры распределения проверяются на согласованной HTTP-границе: ручная доля/автозакрепление, Pin без пересчёта, Unpin, ID-порядок остатка, нулевой остаток, невозможная сумма, disabled, недопустимый ввод, конкурентные версии, атомарность, независимость потоков и повторное открытие БД. Подменяется только клиент Keitaro. Проверяются поиск, ошибки и пустые ответы, поддерживаемость потоков, исходные доли, повторное открытие БД, конфликты, конкурентное первое открытие и независимость сетевых ожиданий, CSRF и Host.

Отдельный opt-in тест строит **тот же образ** и через HTTP проверяет реальный HTTP-адаптер, пагинацию кампаний, React/статические assets, ошибки/неправильный JSON, сохранение базы после пересоздания контейнера и отказ запуска при ошибке миграции:

```sh
COMPOSE_TEST=1 .venv/bin/python -m pytest -m compose -q
# Или API + Compose вместе:
COMPOSE_TEST=1 .venv/bin/python -m pytest -q
```

Тест использует `compose.test.yml`, локальный fake HTTP Keitaro и фиксированные localhost-порты 18080/18081. Настройки `.env` перекрываются безопасными тестовыми значениями. Порты можно переопределить через `TEST_APP_PORT` и `TEST_FIXTURE_PORT` (например, 18280/18281). Проект `adrobot-issue11-test` и его тестовый том удаляются по завершении. Не запускайте два таких теста одновременно; не используйте это имя проекта для своих данных. В production compose остаётся только один сервис приложения. Для ручной демонстрации с fake вместо Keitaro:

```sh
docker compose -p adrobot-demo -f compose.yml -f compose.test.yml up --build -d
# http://127.0.0.1:18080 — только синтетические данные
docker compose -p adrobot-demo -f compose.yml -f compose.test.yml down --volumes
```

Предыдущая проверка #9: API + Compose HTTP — **27 тестов проходили**; TypeScript/Vite build проходил. Playwright на локальном fake: поиск, пустой результат/пустые потоки, повторное открытие выбранной кампании, ошибка с сохранением последнего результата, сравнение конфликта и клавиатурный переход проверены. На ширинах 1440 и 390 нет горизонтального переполнения страницы (таблицы прокручиваются отдельно). `npm audit` и `pip-audit -r requirements.txt` не находят известных уязвимостей на момент проверки. Возможен предупреждающий вывод Starlette о будущем переходе TestClient с httpx на httpx2.

Проверка #10 до слияния: **61 тест проходит** при `COMPOSE_TEST=1` (API + Docker Compose HTTP), включая все предыдущие тесты; TypeScript/Vite build внутри образа проходит. TDD: зафиксированы падения до реализации preview, GEO, поиска оффера, настроек, имени и HTTP-адаптера, затем успешные прогоны. Playwright на packaged fake проверил форму, поиск по имени/ID и пустой результат, выбор другого оффера, нормализацию GEO, оба варианта префикса, ошибку GEO и сброс устаревшего резюме, Tab/Enter. На ширинах 1440 и 390 нет горизонтального переполнения; viewport-снимки формы/резюме проверены отдельно. Фокусируемая skip-ссылка скрыта при обычной работе и видна при фокусе клавиатурой. Ручная браузерная проверка выполнена на синтетических данных, не на живом стенде.

При реализации #12 Playwright на синтетическом Compose проверил ввод доли и отправку Enter, Pin/Unpin, отказ невозможной суммы, дробный ввод и сохранение после перезагрузки страницы. На 1440/390 px переполнения страницы нет; широкие таблицы прокручиваются отдельно. Механический UI-detector не сообщил замечаний. Предыдущие проверки #9 выше относятся к базовому срезу.

После слияния `integration/keitaro-wrapper` с #12: **81 тест проходит** (API + Compose HTTP), в том числе с переопределёнными портами `TEST_APP_PORT=18380 TEST_FIXTURE_PORT=18381`. Объединённый образ успешно проходит TypeScript/Vite build. Это повторная автоматическая проверка; браузерные сценарии #10 и #12 выше были проверены отдельно до слияния.

**Это не проверка живого Keitaro.** Реальный стенд при реализации #9 не вызывался. Пагинация, схемы ответа и состояние сервера проверены на fake по публичному контракту, а не подтверждены для всех версий Keitaro. Отдельная живая приёмка возможна только с разрешения владельца и на выделенных сущностях.

## Проверка ссылки `preview`

Назначение ссылки из [демонстрации редактора](https://www.youtube.com/watch?v=jNloscEWCjA) **не установлено**. Доступные исходные материалы — #8, #5 и [первоначальное исследование Admin API](https://github.com/DanGrigorenko/Adrobot/blob/985ad622d65e742666835ebb27ffe4ead9c757d3/docs/research/keitaro-admin-api.md) — не задают её URL. По [публичному справочнику Admin API](https://admin-api.docs.keitaro.io/) в офферах есть `preview_path`, но это не доказывает адрес именно этой ссылки и не задаёт однозначный URL предпросмотра потока. Прямое чтение страницы справочника из среды проверки дополнительно ограничено ошибкой сертификата; нельзя выдавать индексированную схему за просмотр исходного кода демонстрации.

Поэтому произвольный URL не подставлен, `action_payload` не назван предпросмотром, и ссылка `preview` не воспроизведена. Ссылка «Открыть Keitaro» — отдельная навигация в админ-панель кампании, не preview. Для воспроизведения preview нужны подтверждённые исходники/адрес назначения и решение владельца при неоднозначности. Этот результат записан здесь и в отчёте, **не в GitHub issue**, поскольку запись в задачи в этой сессии запрещена. Соответствующий пункт #9 остаётся организационно незакрытым.
