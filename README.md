# Adrobot

Локальный интерфейс кампаний Keitaro. Срезы #9 и #12: поиск кампаний, просмотр потоков и привязок, сохраняемые версионируемые черновики, изменение долей и Pin/Unpin. Creator, Removed, Cancel и Push относятся к следующим срезам и здесь не реализованы. Приложение **не записывает в Keitaro**.

## Запуск

Нужны Docker Engine и Docker Compose v2.24.4+ (или v5). Node.js и Python на машине проверяющего не требуются.

```sh
cp .env.example .env
# В локальном .env задайте адрес вашего Keitaro и серверный API-ключ.
docker compose up --build -d
docker compose ps
```

Откройте **http://127.0.0.1:8000**. FastAPI раздаёт React-сборку и API с одного адреса. Frontend собирается в Docker. Проверка готовности: `curl --fail http://127.0.0.1:8000/api/health`.

- `KEITARO_BASE_URL` — корневой HTTP(S) адрес Keitaro, **без** `/admin_api/v1`, query, fragment, имени пользователя и пароля. Для удалённого Keitaro используйте HTTPS. Ключ передаётся только сервером в заголовке `Api-Key`; в UI, bundle и журналы он не попадает.
- `KEITARO_API_KEY` — ключ с правами чтения кампаний, потоков и каталога офферов. `.env` не коммитится и исключён из Docker build context. Не запускайте обычные тесты с настоящими секретами.
- `APP_ORIGIN` — точный адрес браузера, по умолчанию `http://127.0.0.1:8000`. Изменяющие HTTP-запросы требуют совпадающий `Origin`, заголовок `X-Adrobot-Request: 1` и отсутствие `Sec-Fetch-Site: cross-site`; действия над черновиком защищены этой проверкой. GET открытия потока идемпотентно сохраняет только начальный локальный снимок. Проверяется Host; CORS не открыт.
- SQLite находится в именованном томе `sqlite-data`, `/data/adrobot.sqlite`. Один контейнер приложения, один процесс backend. Не масштабируйте приложение и не открывайте порт в интернет. Для удалённого доступа используйте SSH-туннель.
- Alembic выполняет миграции в ASGI startup **до приёма запросов**. Ошибка останавливает запуск, а не создаёт пустую БД в обход миграций. Healthcheck не проверяет доступность Keitaro: сетевые ошибки показаны отдельно в UI.

`docker compose down` сохраняет данные. `docker compose down --volumes` **удаляет** их.

## Что проверять в интерфейсе

1. Найдите кампанию по названию без учёта регистра или точному ID. Выберите её; сверху находятся имя, ID, время успешного чтения, ссылка в Keitaro и обновление потоков. Выбор сохраняется в URL, обновление страницы снова открывает кампанию.
2. Откройте Regular/Default со схемой `landings`. Впервые создаются база и черновик версии 1; все привязки незакреплены. Название и ID оффера, доля, статус и Pin показаны отдельно. Прямой редирект и неизвестные типы — только просмотр, без создания черновика.
3. Убедитесь, что исходные 70/30 остаются 70/30. Активная запись 0% не становится disabled. Disabled сохраняет долю, но не участвует в сумме активных. 20/20, дробные и выходящие за диапазон значения показаны без исправления с причиной запрета будущей публикации.
4. Измените привязки выделенного тестового потока непосредственно в Keitaro **только с разрешения владельца**, затем обновите потоки. Старые база и черновик не заменяются; появляется конфликт и раскрываемое сравнение с текущим состоянием. Простая перестановка привязок не является конфликтом. Этот срез не разрешает конфликт и ничего не публикует.
5. Проверьте поиск без результата, кампанию без потоков, сетевую ошибку и повтор. При неудачном обновлении уже прочитанные данные остаются с предупреждением об устаревании. Поля и кнопки доступны с клавиатуры; узкие таблицы прокручиваются горизонтально.
6. Для активной привязки задайте целое 0–100 и нажмите «Применить» (или Enter). Доля закрепляется, остаток сервер делит между незакреплёнными; остаточные единицы — по возрастанию ID. Например, 34/33/33 → задать первому 50 → 50 Pin/25/25 → Unpin → 34/33/33. Pin без ввода доли ничего не перераспределяет; disabled не редактируется.
7. При закреплённых 60% попробуйте другой активной привязке задать 50%: отказ сохраняет весь черновик и Pin. Дробный, отрицательный и превышающий 100 ввод не принимается. Откройте две вкладки: действие с прежней версией отклоняется с предложением перечитать потоки. Другие потоки независимы.
8. Перезапустите/пересоздайте контейнер без удаления тома: база, черновик, версия и Pin остаются прежними. Обновление потоков не отменяет изменения и не выравнивает исходные 70/30.

Контракт действия: `POST /api/campaigns/{campaign_id}/streams/{stream_id}/actions`, JSON `{"version":1,"action":"share","offer_id":9,"share":50}`. Другие действия: `pin`, `unpin` без `share`. Ответ — сохранённые `version`, `base`, `bindings`; 409 означает устаревшую версию или неподдерживаемый поток, 422 — недопустимое действие. Проверка версии и сохранение защищены одной SQLite-транзакцией. Сетевое чтение поддерживаемости выполняется до транзакции; записи в Keitaro нет.

### Резервная копия остановленной БД

Копируйте только после остановки приложения, не во время записи:

```sh
docker compose stop app
mkdir -p backups
docker compose cp app:/data/adrobot.sqlite backups/adrobot.sqlite
docker compose start app
```

Резервная копия содержит локальные снимки кампаний/привязок; храните её как приватные данные. Не добавляйте её в Git.

## Тесты без настоящего Keitaro

Для API-тестов нужен Python 3.13+:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

API-тесты используют настоящие FastAPI, сценарии чтения/редактирования Editor, миграции и файловую SQLite. Примеры распределения проверяются на согласованной HTTP-границе: ручная доля/автозакрепление, Pin без пересчёта, Unpin, ID-порядок остатка, нулевой остаток, невозможная сумма, disabled, недопустимый ввод, конкурентные версии, атомарность, независимость потоков и повторное открытие БД. Подменяется только клиент Keitaro. Проверяются поиск, ошибки и пустые ответы, поддерживаемость потоков, исходные доли, повторное открытие БД, конфликты, конкурентное первое открытие и независимость сетевых ожиданий, CSRF и Host.

Отдельный opt-in тест строит **тот же образ** и через HTTP проверяет реальный HTTP-адаптер, пагинацию кампаний, React/статические assets, ошибки/неправильный JSON, сохранение базы после пересоздания контейнера и отказ запуска при ошибке миграции:

```sh
COMPOSE_TEST=1 .venv/bin/python -m pytest -m compose -q
# Или API + Compose вместе:
COMPOSE_TEST=1 .venv/bin/python -m pytest -q
```

Тест использует `compose.test.yml`, локальный fake HTTP Keitaro и фиксированные localhost-порты 18080/18081. Настройки `.env` перекрываются безопасными тестовыми значениями. Порты можно переопределить через `TEST_APP_PORT` и `TEST_FIXTURE_PORT` (например, 18280/18281). Проект `adrobot-issue12-test` и его тестовый том удаляются по завершении. Не запускайте два таких теста одновременно; не используйте это имя проекта для своих данных. В production compose остаётся только один сервис приложения. Для ручной демонстрации с fake вместо Keitaro:

```sh
docker compose -p adrobot-demo -f compose.yml -f compose.test.yml up --build -d
# http://127.0.0.1:18080 — только синтетические данные
docker compose -p adrobot-demo -f compose.yml -f compose.test.yml down --volumes
```

Фактическая проверка срезов #9/#12: API + Compose HTTP — **47 тестов проходят**; TypeScript/Vite build проходит. Playwright на локальном fake: поиск, пустой результат/пустые потоки, повторное открытие выбранной кампании, ошибка с сохранением последнего результата, сравнение конфликта и клавиатурный переход проверены. На ширинах 1440 и 390 нет горизонтального переполнения страницы (таблицы прокручиваются отдельно). `npm audit` и `pip-audit -r requirements.txt` не находят известных уязвимостей на момент проверки. Возможен предупреждающий вывод Starlette о будущем переходе TestClient с httpx на httpx2.

При реализации #12 Playwright на синтетическом Compose проверил ввод доли и отправку Enter, Pin/Unpin, отказ невозможной суммы, дробный ввод и сохранение после перезагрузки страницы. На 1440/390 px переполнения страницы нет; широкие таблицы прокручиваются отдельно. Механический UI-detector не сообщил замечаний. Предыдущие проверки #9 выше относятся к базовому срезу.

**Это не проверка живого Keitaro.** Реальный стенд при реализации #9 не вызывался. Пагинация, схемы ответа и состояние сервера проверены на fake по публичному контракту, а не подтверждены для всех версий Keitaro. Отдельная живая приёмка возможна только с разрешения владельца и на выделенных сущностях.

## Проверка ссылки `preview`

Назначение ссылки из [демонстрации редактора](https://www.youtube.com/watch?v=jNloscEWCjA) **не установлено**. Доступные исходные материалы — #8, #5 и [первоначальное исследование Admin API](https://github.com/DanGrigorenko/Adrobot/blob/985ad622d65e742666835ebb27ffe4ead9c757d3/docs/research/keitaro-admin-api.md) — не задают её URL. По [публичному справочнику Admin API](https://admin-api.docs.keitaro.io/) в офферах есть `preview_path`, но это не доказывает адрес именно этой ссылки и не задаёт однозначный URL предпросмотра потока. Прямое чтение страницы справочника из среды проверки дополнительно ограничено ошибкой сертификата; нельзя выдавать индексированную схему за просмотр исходного кода демонстрации.

Поэтому произвольный URL не подставлен, `action_payload` не назван предпросмотром, и ссылка `preview` не воспроизведена. Ссылка «Открыть Keitaro» — отдельная навигация в админ-панель кампании, не preview. Для воспроизведения preview нужны подтверждённые исходники/адрес назначения и решение владельца при неоднозначности. Этот результат записан здесь и в отчёте, **не в GitHub issue**, поскольку запись в задачи в этой сессии запрещена. Соответствующий пункт #9 остаётся организационно незакрытым.
